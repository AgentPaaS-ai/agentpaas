## RPC methods

### workflow_input

Response (stage 0):
```json
{"available": false}
```

Response (mid-stage):
```json
{
  "available": true,
  "handoff": { ... B34 envelope fields ... },
  "artifact_refs": []
}
```

Error codes:
- `WORKFLOW_CONTEXT_UNAVAILABLE` — not a pipeline stage
- `no_active_invoke` — no active invoke
- `STALE_LEASE` — lease expired or terminal

### commit_handoff

Params (worker-controlled, identity fields ignored):
```json
{
  "schema": "example/research-notes/v1",
  "context": { ... },
  "artifacts": [ ... ]
}
```

Response:
```json
{
  "accepted": true,
  "handoff_digest": "sha256:...",
  "staged": true
}
```

Error codes:
- `HANDOFF_NOT_ALLOWED` — final stage or non-pipeline
- `HANDOFF_INVALID` — missing required params
- `HANDOFF_RESERVED_KEY` — reserved key in context
- `HANDOFF_CONTEXT_OVERSIZE` — context > 256 KiB
- `HANDOFF_CONFLICT` — different bytes, same handoff_id
- `STALE_LEASE` — lease expired or terminal

## Design decisions

**Pipeline stage context:** Stored on `rpcInvokeState.pipelineCtx` as a pointer (nil = non-pipeline). Injected by daemon via `SetPipelineContext()` before Python worker starts. Pattern matches `SetProgressMetadata`.

**Identity enforcement:** Worker-supplied identity fields (`workflow_id`, `run_id`, etc.) in commit_handoff params are completely ignored. Harness builds the full envelope from its own invoke identity.

**Idempotency:** Digest computed from content-relevant fields only (excludes `CreatedAt`, `schema_version`). Same digest → idempotent success; different digest, same handoff_id → conflict.

**Validation:** All commit_handoff candidates pass through `pipeline.ValidateHandoffEnvelope` before staging. Validation codes are mapped to RPC error codes.

**Default classification:** Falls back to "internal" when not set in pipeline context.

**Producer digest:** Computed as sha256 of the context bytes at commit time.
